# 계획 수정 2 — 진입 안내와 디자인 역할

결정일: 2026-09-27. 이전의 루트 404 정책과 Codex가 디자인을 먼저 만드는 방식보다 이 결정이 우선한다.

## 도메인의 첫 화면

`https://undery.link/`는 방문자가 어디로 들어갈지 알 수 있도록 안내한다.

| 선택지 | 안내할 역할                  | 이동 주소 |
| ------ | ---------------------------- | --------- |
| Coding | 개발 글과 기술 기록          | `/coding` |
| Game   | 게임 활동, 하이라이트와 사진 | `/game`   |
| Whoami | 자기소개와 댓글              | `/whoami` |

루트는 HTTP 200으로 안내 화면을 제공한다. 방문자가 직접 선택하며 특정 영역으로 자동 이동하지 않는다. 각 영역의 전체 주소로 바로 접속하는 방식도 유지한다. 루트에 상세 소개나 최신 글·미디어를 모으는 기능은 이번 변경에 포함하지 않는다.

HTTP·www 주소는 경로와 쿼리를 보존해 `https://undery.link`로 308 정규화한다. `/?from=profile`도 같은 안내 화면이며 `/#game` 같은 해시는 서버의 루트 응답을 바꾸지 않는다. `/index`, `/index.html`, `/develop`, `/blog`, 미등록 주소의 404는 유지한다.

각 영역의 콘텐츠·검색·추천·사이트맵은 계속 분리한다. 루트의 목적지 안내는 그 분리 정책의 의도된 예외다. 영역에서 선택 안내로 돌아가는 링크와 그 배치는 사용자의 시안을 따른다.

루트의 canonical은 `/`로 두고 사이트 전반을 소개하는 공유 주소로 사용할 수 있다. 특정 콘텐츠를 소개할 때는 영역·상세 주소를 사용한다. `/sitemap.xml`에는 공개된 루트만, 영역별 사이트맵에는 해당 영역 주소만 포함한다. 검색 허용 시점은 기존 공개 검증 절차를 따른다.

## 디자인 역할

- **사용자:** 모든 화면의 디자인 원안, 레이아웃, 분위기, 색상, 이미지, 콘텐츠 배치와 최종 방향을 정한다.
- **Codex:** 사용자가 제공한 디자인을 바탕으로 더 세련되고 완성도 있게 다듬는다. 의도와 개성을 유지하면서 간격·정렬·글꼴 크기와 굵기·시각적 위계·색 대비·구성의 일관성·모바일 표현·상호작용을 개선한다.
- 원안의 구조나 브랜딩을 크게 바꾸는 경우에는 별도 제안으로 구분하고 임의로 대체하지 않는다.
- 디자인이 없는 화면의 새 콘셉트·완성 시안을 먼저 만들지 않는다. 기존 기반 화면과 그 문구는 최종 시안으로 확정하지 않는다.
- 기능·서버·데이터 작업은 별도로 요청된 범위에서 진행하며, 디자인을 먼저 정하는 근거로 사용하지 않는다.

작업 흐름은 **사용자 시안 → 의도 확인 → 시각적 완성도 개선 → 데스크톱·모바일 비교 → 사용자 피드백 반영**으로 둔다. 이미 분명한 의도는 다시 묻지 않고 반영한다. 문서 편집이나 일반적인 시각 보정마다 추가 승인 단계를 두는 의미는 아니다.

## 구현에 반영할 작업

사용자 시안을 바탕으로 루트 화면을 구현하는 작업에서 다음을 함께 바꾼다.

1. `src/app/page.tsx`: 루트 404를 목적지 안내 화면으로 교체한다.
2. 루트 canonical·공유 정보·사이트맵을 추가한다. 공개 전에는 현재 검색 수집 차단을 유지한다.
3. `deploy/nginx/undery.link.conf`: 대표 HTTPS 루트는 앱으로 전달하고 HTTP·www 루트는 대표 주소로 정규화한다.
4. `scripts/smoke.mjs`, `tests/proxy.py`: 루트 404 기대값을 안내 화면 200/정규화 308 검사로 바꾸고 세 선택 링크를 확인한다. 미지원 경로의 404 검사는 유지한다.
5. 사용자 시안에 선택 안내로 돌아가는 링크가 있으면 영역 경계 검사도 그 링크를 허용하도록 조정한다.
6. 새 결과를 검증 기록에 추가한다. 기존 검증 결과를 새 정책 검증으로 재사용하지 않는다.

## 현재 반영 상태

이번 수정은 계획·작업 지침·운영 절차·변경 이력에 반영했다. 앱 코드, Nginx 설정안, 기존 검사, 미리보기 화면, 운영 사이트는 아직 수정하지 않았다. 기존의 루트 404 구현은 새 계획 기준에서 변경 대기 항목이다. 루트와 각 영역의 최종 화면은 사용자 디자인을 기준으로 다듬는다.
